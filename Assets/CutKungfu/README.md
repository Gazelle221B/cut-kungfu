# カット!カンフー — テストプレイ用プロトタイプ

GDD v0.2 の 13章「最初の試作」を、グレーボックス(箱とカプセル)で動く形にしたもの。
設計資料: [GDD v0.2](../../GDD_cut_kungfu_v0.2.md) / [企画書 v0.1](../../PITCH_cut_kungfu_v0.1.md) / [TDD v0.1](../../docs/TDD_cut_kungfu_v0.1.md)
検証する仮説はひとつ: **コミット時間を入れると、包囲時に多ポーズ技の使用が減る**(GDD 14章)。

## 動かし方

1. Unity 6000.6.10f1 でこのプロジェクトを開く
2. `Assets/CutKungfu/Scenes/Prototype.unity` を開いて再生
3. シーンを作り直したいときはメニュー **Cut Kungfu > Build Prototype Scene**(マテリアル・プレハブ・サブシーン・UI 設定まで全部コードから再生成する)

| 捌き(スロー中: 直前のポーズを戻す) | K / 右クリック | RB |

ブリック4種(GDD 8章): 掌底(正面単体) / 回し蹴り(周囲) / 飛び蹴り(遠くまで届き、経路上も当たる) / 机上の着地(机の上にだけ置ける。範囲が広く映え倍率が高い)。

範囲技(回し蹴り・机上の着地)が1回の技で同じ敵に与えるダメージは、合計で最大体力の 80% まで(超えた分は灰色の「上限」表示)。とどめは単体技に任せる。
飛び蹴りは、到達点で狙った敵には上限なしで当たるが、経路で巻き込んだ敵への打撃は範囲技と同じ上限の対象になる。

## 1プレイの流れ

1. ウェーブ開始時のフィルムゲージは 50(3ポーズ分)。通常攻撃と捌きで溜める(命中 +5、捌き成功 +20)。4ポーズを置くには溜めてから止める必要がある
2. Space でスロー(固定費 20)。画面がセピアになり、敵の頭上に「次に殴ってくるまでの秒数」が出る
3. ポーズを最大4つ置く(1個 10)。最後のポーズの足元にフィルム帯が出て「今解除したら何秒動けないか」を1コマ=0.1秒で予告する。今解除すると技の途中か硬直中に殴ってくる敵は、頭上の秒数が白枠の赤になる
4. もう一度 Space で切る。置いた順に人影を辿って打つ。威力は置いた数で ×1.0 / 1.6 / 2.4 / 3.5。**実行中も殴られる**(殴られたら残りのポーズは消える)
5. 最後のポーズの後、硬直(0.3 + 0.2/0.5/0.9/1.5 秒)。硬直中の被弾は **1.5倍のカウンターヒット**で、殴られても硬直は短くならない
6. 体力ゼロで「NG!」→ 2秒以内に同じウェーブの頭から「テイク2」。理由(硬直中に殴られた、何ポーズだったか)を表示する

ウェーブは GDD 6章の2盤面を交互に繰り返す: **A = 敵1体・背後は壁** / **B = 敵3体の包囲**。

## プレイテストの進め方(GDD 14章)

- 条件 A(コミット時間あり)と B(なし)を F1 で切り替える。**プレイ順は人ごとに入れ替える**
- 同じ部屋・同じ敵配置・同じゲージ量(ウェーブ開始時は 50。`GaugeAtWaveStart`)。敵の乱数もウェーブ番号で固定
- **条件 A(コミット時間あり)には、硬直と「硬直中の被弾は1.5倍」(カウンターヒット)の両方が含まれる。** 条件 B は硬直が無いのでカウンターヒットも起きない。差が出たとき、硬直の長さだけの効果かを切り分けたければ `CounterHitMultiplier` を 1 にした条件 A で追加に試す
- 方向が見えなければ `tuning.json` の `CommitScale` を 2 にして極端な値で試す
- F2 で条件×包囲人数ごとの平均ポーズ数がその場で見える
- プレイ後の質問: ①今、何を目標にしていたか ②いちばん迷った瞬間はどこか ③なぜ NG になったと思うか ④次のテイクで何を変えるか。対立仮説を切り分けるため「置く操作そのものは面倒だったか」は別に聞く

### 記録(CSV)

エディタでは `<プロジェクト>/Playtests/session_*.csv`、ビルドでは `persistentDataPath/Playtests/`。1行1イベント。

| 列 | 意味 |
|---|---|
| kind | `cut`(解除〜硬直明けで1サンプル) / `cut_cancelled`(1個も置かずに解除) / `player_hit` / `ng` / `wave_clear` / `wave_start` / `condition_changed` |
| enemies_alive / enemies_near | スロー突入時に生きていた敵 / 半径4m以内の敵(包囲の強さ) |
| gauge_before / max_affordable | スロー突入時のゲージ(固定費を払う前) / そのゲージで置けた最大のポーズ数 |
| poses / sequence | 置いた数 / 置いた順(`palm>spin>fly`) |
| commit_time / hit_during_commit | その技の硬直 / 硬直中に殴られたか |
| kills / hae | その技で倒した数 / 映え点 |
| slow_seconds / timed_out | スローに居た実時間 / 4秒の制限で切れたか |
| undos / rejects | 戻した回数 / 置こうとして置けなかった回数 |
| min_enemy_eta | スロー突入時、最も早く殴ってくる敵までの見込み秒数(包囲の切迫度) |
| interrupted | 実行中に殴られて中断したか |
| area_cap_hits | その技で、範囲技の打撃が上限(敵の最大体力の 80%)に掛かって削られた回数 |

主指標 = `kind=cut` の `poses` を `commit_enabled × enemies_alive` で平均。悪化させないもの = `cut + cut_cancelled` の件数(スロー使用回数)。
「置かなかった」と「ゲージが足りず置けなかった」は `poses` と `max_affordable` を比べて分ける(`poses < max_affordable` なら自分で止めた)。
対立仮説(置く操作が面倒なだけ)の切り分けには `slow_seconds`・`timed_out`・`undos`・`rejects` を見る。条件 A で置く数が減ったのに、これらが条件 B と変わらなければ「操作の面倒さ」では説明しにくい。

## 調整値

`Assets/StreamingAssets/CutKungfu/tuning.json`。**再生中に保存すると1秒以内に反映**される(ビルド後も同じファイルで調整できる)。
既定値は `Scripts/Core/Tuning.cs` の `Tuning.Default`(GDD の【】仮値)。

### GDD の仮値から変えたもの

別系統のモデル(GPT-6.2 Sol / Gemini 4 Neon)のレビューで、GDD の仮値のままでは検証したい判断が成立しないと分かった箇所を変えている。

| 項目 | GDD 仮値 | 試作の値 | 理由 |
|---|---|---|---|
| 範囲技が同じ敵に与える合計 | — | 1回の技で敵の最大体力の 80% まで(`AreaDamageCapRatio`、1以上で無効)。上限に掛かった打撃は灰色の「上限」表示。飛び蹴りの巻き込み(到達点で狙った敵以外)も対象 | 机上の着地+回し蹴りなどの混成で、4個技で包囲を1回で全滅できた(`SurroundBalanceTests.MixedAreaCombos_*`)。とどめは単体技(掌底・飛び蹴り)に任せる |
| 同じブリックの繰り返し | — | 2回目×0.5、3回目×0.25(`RepeatBrickScale`) | 回し蹴り×4で包囲を1回で全滅でき、硬直を踏み倒せた(`SurroundBalanceTests`)。議事録の「同じ技の繰り返しは減点」と同じ方向 |
| 敵の体力 | — | 90 | 1体1ポーズに散らした技で全員を倒し、硬直を踏み倒す解を消す |
| 追加の硬直 | 0.2/0.4/0.7/1.1 | 0.2/0.5/0.9/1.5 | 最後のポーズで空き地へ逃げると、敵が詰める前に硬直が明けていた |
| 実行中の無敵 | — | なし | スロー中に予備動作を読む意味を残す(TDD 7章の「中断」) |
| 硬直中の被弾 | — | 1.5倍 | 硬直の罰を体力でも見せる |
| 開始時のゲージ | 指定なし(14章は「同じゲージ量」のみ。前版の試作は満タン) | 50 | 「今止めるか、溜めて待つか」(GDD 6章 第3の判断)を作る |
| 飛び蹴りの到達 | — | 5.5m | 逃げ技として強すぎた |

どれも `tuning.json` で戻せる。

敵の体力 90 は「散らした4ポーズでは全滅できず、1体に集中すれば3ポーズで倒せる」値。これが崩れると「全員を一度に片付けて硬直を踏み倒す」解が生まれ、検証したい判断が消える。前提は `CutRulesTests.Balance_SpreadingCannotWipe_ButFocusingKills` で固定している。

## 設計

```
Core (純粋 C#)          ルール・調整値・幾何・記録形式。ECS も UnityEngine も知らない
  ↑
Gameplay (ECS ISystem)  止める/置く/切る、通常攻防、雑魚AI、ダメージ解決、進行
  ↑            ↑
Authoring      Presentation (SystemBase)   入力ブリッジ・カメラ・スロー演出・HUD・効果音・JSON・CSV
(ベイカー)        └ PresentationRoot (唯一の MonoBehaviour。参照の受け渡しだけ)
  ↑
Editor (シーン生成)
```

- **入力は意図に変換してから渡す**: `InputBridgeSystem` が Input System を読み、デバイスを知らない `PlayerInput` シングルトンに書く。ロジックはこれしか見ないので、テストは入力を直接書いて回せる(`GameplayWorldTests`)
- **攻撃は要求を積むだけ**: 攻撃側は `DamageRequest` を積み、捌き・無敵・ゲージ・NG理由・ヒットストップは `DamageSystem` が1か所で決める
- **時間は GameClock に集約**: `Time.timeScale` は使わない。スロー・ヒットストップ・NG の停止はすべて `GameClockSystem`
- **手応えは出来事で流す**: ロジックは `FeedbackEvent` / `TelemetryEvent` を積むだけ。HUD・効果音・CSV は Presentation が読んで消す
- **動きの生成は差し替え口**: `Core/CutMotion.cs` は MotionBricks の代わりの仮実装(根の位置と向きだけ補間)。`CutExecutionSystem` は区間(始点・終点・向き・時間)を渡し、位置・回転・接触フレーム・終了を受け取るだけなので、MotionBricks(com.unity.ai.inference で ONNX 推論)が独自の根の回転や接触タイミングを持っていても戦闘側は変わらない
- **見た目は一切同梱しない**: 日本語フォントは OS のフォントから実行時に作り、効果音は起動時に波形を合成する

## 既知の制限(試作の範囲外)

- MotionBricks による動作生成は未接続(企画書 6章の段階①「技術確認」は別作業)。打撃の当たりは XZ 平面の円とカプセルで判定
- 敵は雑魚のみ。大男・飛び道具・マッハ・ズーム・カット評価・通し再生・物語は作らない(GDD 13章)
- キャラクターは箱とカプセル。アニメーションは無い
